## 二、P0 开发任务（第一版必须做）

### 任务 1：虚拟对手系统 [V1-01]

| 项 | 内容 |
|---|---|
| 开发量 | 3-4天 |
| 依赖 | 无 |
| 交付物 | 虚拟对手数据模型 + 日历独立推进引擎 + PK系统 + 首页/个人中心触点 |

子任务拆解：

| 序 | 子任务 | 工作量 | 说明 |
|---|---|---|---|
| 1.1 | 虚拟对手数据模型 | 0.5d | VirtualOpponent类：id/nickname/level/weeklyTrainings/weeklyWeight/avatarSeed/人设/动态 |
| 1.2 | 100个对手数据生成 | 0.5d | 本地随机种子生成，按4层水平分布（每层25个），符合健身规律。调优说明：原300+工作量大，v1先上100个验证参与率 |
| 1.3 | 日历独立推进引擎 | 1d | 每周日凌晨基于日历推进，不依赖用户事件。胜负分布算法（碾压25%/胶着50%/被吊打25%） |
| 1.4 | PK系统 + UI触点 | 1d | 首页卡片"超越X%同水平用户"、个人中心PK对比卡片、训练完成弹窗 |
| 1.5 | 冷启动匹配 | 0.5d | 新手引导问"每周打算练几次"，按回答初始化匹配层 |
| 1.6 | 对手叙事系统 | 0.5d | 人设模板 + 随机动态生成（"今天加班没练"等） |

验收标准：
- 对手数据符合健身规律（每周1-7次，每次40-90min，重量递进）
- 用户不打开APP一周后，对手数据已变化
- 胜负分布非恒定（不是每次都5-15%差距）

验收标准：
- 被邀请者首次启动APP时剪贴板含邀请码→自动提示激活

- 微信扫码落地页→应用商店→安装→启动激活，全流程跑通

调优说明：
- v1不引入服务器，裂变流程通过UX设计补偿
- 体验差距仅1次点击（扫码→确认 vs 服务器方案扫码→自动激活）
- 开发量2-3天 vs 服务器方案15-20天，节省12-17天
- v1.5阶段再引入服务器层彻底优化

## 七、风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 虚拟对手被识破 | 中 | 信任受损 | 日历独立推进+叙事+胜负分布真实化 |
| 教学动图版权问题 | 中 | 法律风险 | 使用CC0资源或自行制作序列帧 |
| Deeplink在鸿蒙适配 | 中 | 分享码导入失败 | 6位码兜底，Deeplink逐步调试 |
| 100个对手数据生成工作量大 | 低 | 开发延期 | 算法批量生成+随机校验 |
| 广告SDK鸿蒙不适配 | 中 | 广告收入归零 | 华为广告优先，穿山甲兜底，失败静默 |
| App Linking剪贴板检测被系统拦截 | 中 | 一键激活失效 | Android 10+剪贴板读取限制，需提示用户手动粘贴短链，6位码兜底 |
| App Linking被微信/浏览器拦截 | 中 | 拉起APP失败 | H5落地页兜底→用户点击下载→安装后首次启动检测剪贴板 |
| 剪贴板隐私提示被用户反感 | 低 | 差评 | 首次读取仅顶部浮条单次提示，不强制弹窗，用户可永久关闭 |

> v1.2调优说明：新增4项风险来自V1-08a一键裂变流程优化，App Linking和剪贴板检测在鸿蒙生态适配存在不确定性，已准备多级兜底方案。
