## 一、版本定位

### 1.1 一句话定位

> **v1 = 零付费墙的获客与留存验证阶段。全免费开放，用"无打扰纯本地"差异化获客，用深钩子验证留存。**

### 1.2 核心策略

| 策略 | 说明 |
|------|------|
| 全免费 | 无 Pro、无订阅、无付费墙。用户零摩擦进入 |
| 深留存钩子 | 虚拟对手 + 教学裂变 + 数据沉淀锚点 + 7天留存链 |
| 克制广告 | 仅2个激励视频位，用户主动触发，不打断训练 |
| 获客驱动 | HarmonyOS原生红利 + ASO + 教学裂变 + 小红书内容 |
| 已实现不启用 | Pro/兑换码已在Phase 2编码实现，v1不启用，后续版本直接开关拨通 |

### 1.3 与原方案的关键差异

| 维度 | 原运营优化方案 | v1 获客留存版 |
|------|--------------|--------------|
| Pro体系 | 开放（月卡/年卡/终身+试用） | 不开放，全免费 |
| 历史记录限制 | 7天查看限制 | 不限制，全免费可查 |
| 高级统计 | Pro专属 | 全免费开放 |
| 裂变激励 | Pro时长激励 | 功能解锁（教学信息）+ 虚拟荣誉 |
| 付费转化 | v1即开始 | v1不转化，v2启动 |
| 广告位 | 2个激励视频 | 2个激励视频（保留，但"Pro试用延长"改为"看广告得1次高级报告"） |

## 二、v1 新增核心功能

### 2.1 虚拟对手——解决单机无社交的粘性短板

预埋100个虚拟用户训练数据，按真实日历时间独立演进（不依赖用户训练事件），让用户有"和真人PK"的感觉。

> 调优说明：原方案300+对手数据预埋工作量大，建议v1阶段先上100个（覆盖4个水平层级，每层25个），验证参与率后再扩量至300+。100个对手已足够支撑"每周匹配池轮换"和"冷启动分层匹配"的核心逻辑。

核心改进（相比原方案）：
- 对手按日历时间独立推进，用户不开APP对手也在"练"
- 扩到300+对手，每周匹配池轮换
- 引入对手叙事（人设+偶尔动态"今天加班没练"）
- 胜负分布真实化：有碾压局、胶着局、被吊打局，不是永远5-15%差距
- 冷启动匹配：新手引导时问"你每周打算练几次？"，按回答初始化匹配层

### 2.2 教学信息系统——裂变核心驱动力

健身用户刚需痛点：不知道动作怎么做。

内容结构：
- 基础教学（免费）：30个最高频动作·图文要点（v1阶段优先覆盖胸/背/腿/肩/手臂/核心6大肌群的最核心动作）
  > 调优说明：原方案50个基础动作制作量大，建议v1先上做30个最高频动作（每个肌群3-5个），后续版本持续补充
- 进阶教学（裂变解锁）：每邀请1人激活→解锁1个进阶动作（含动图/常见错误/替代动作）
  > 调优说明：原方案解锁3个进阶动作，建议调整为解锁1个，降低用户分享心理门槛，提升邀请意愿
- 专题教学包（裂变里程碑）：累计邀请3人→解锁"卧推完全指南"专题
- 高手教学（裂变里程碑）：累计邀请5人→解锁"渐进超负荷实操"专题

关键设计：
- 教学信息永久解锁，不收回
- 教学可分享→生成分享卡片带邀请码
- 教学带虚拟教练人设署名

### 2.3 教学裂变体系——v1获客引擎

邀请码复用现有HMAC本地验证机制（与兑换码独立密钥）：

- 邀请码格式：FIT-INV-XXXXXX（6位，独立前缀）
- 与分享码FITT-XXXXXX区分（UGC内容，不含权益）
- 激活时机：首启新手引导末尾 / 设置页"我有邀请码"入口

激励分层（全永久解锁，不收回）：

| 被邀请人行为 | 邀请人获得 | 被邀请人获得 |
|---|---|---|
| 激活（输入邀请码+首次训练） | 解锁3个进阶动作教学 + "引路人"徽章 | 7天高级统计全开放体验 |
| 7日留存 | 解锁1个专题教学包 | — |
| 累计邀请3人激活 | 永久免广告看训练报告 + "布道者"徽章 | — |
| 累计邀请5人激活 | 解锁高手教学专题 + 专属虚拟对手皮肤 | — |
| 累计邀请10人激活 | "燃力大使"永久称号 | — |

反作弊：
- HMAC校验邀请人ID≠被邀请人ID（防自邀）
- 一码一绑，激活后不可改
- 单机版无法防多设备刷量，接受损耗（联网版用设备指纹根治）

### 2.4 一键裂变流程——不引入服务器的体验补偿

#### 背景分析

v1阶段不引入服务器，裂变流程存在以下体验摩擦：
- 被邀请者需手动输入邀请码→本地校验→点击确认领取（多步操作）
- 纯本地无法跨设备累计激励次数
- 无法实时更新教学内容（需发版）

引入服务器可解决上述问题，但与v1"纯本地·不追踪"品牌承诺冲突，且开发成本/合规复杂度剧增。**结论：v1不引入服务器，用UX设计补偿流程摩擦，服务器方案延后至v1.5实施。**

#### 一键链路设计（全本地实现）

核心目标：**将"输入邀请码+确认"多步操作压缩为"扫码→自动激活"一键体验**

```
邀请链路：
┌─────────────────────────────────────────────────────────────────────┐
│ 邀请人操作                                                           │
│  ├── 生成分享卡片/海报                                              │
│  │    └── 卡片底部除文字邀请码外，嵌入了"邀请码+元数据"的二维码        │
│  │         └── 二维码内容：fittrack://invite?code=FIT-INV-XXXXXX    │
│  │                                                                  │
│  └── 分享渠道                                                       │
│       ├── 小红书：发布带二维码的训练笔记海报/教学分享图               │
│       ├── 朋友圈：分享带二维码的训练完成卡片                         │
│       └── 微信群：直接分享邀请码文字+fite-link                      │
└─────────────────────────────────────────────────────────────────────┘

被邀请人操作（核心体验）：
┌─────────────────────────────────────────────────────────────────────┐
│ 场景A：微信/小红书扫分享卡片上的二维码                                │
│  ├── 扫码后跳转H5落地页（已有建议，无需服务器，静态托管）            │
│  ├── 落地页展示：APP图标+核心卖点+下载按钮                           │
│  ├── 用户点击下载按钮 → 跳转应用商店下载APP                          │
│  ├── 安装后首次启动 → 自动读取剪贴板内容                             │
│  │    └── 剪贴板含 FIT-INV-格式码 → 自动填充到激活弹窗              │
│  │    └── 用户仅需点击 1次"确认激活"按钮                            │
│  └── 激活成功后：双方奖励自动发放                                    │
├─────────────────────────────────────────────────────────────────────┤
│ 场景B：直接复制邀请码文字                                            │
│  ├── 用户打开APP进入新手引导末尾/设置页"我有邀请码"                  │
│  └── 粘贴邀请码 → 点击激活 → 完成                                   │
├─────────────────────────────────────────────────────────────────────┤
│ 场景C：HarmonyOS App Linking（Phase 2 已编码，v1 配置启用）          │
│  ├── 点击微信内 fite.link/invite/XXXXXX 短链                        │
│  ├── 直接拉起已安装的APP → 跳转激活页                                │
│  └── 未安装则跳应用商店下载 → 同场景A                                │
└─────────────────────────────────────────────────────────────────────┘
```

#### 关键技术实现（全本地）

| 技术点 | 实现方式 | 依赖 |
|---|---|---|
| 二维码生成 | 训练笔记海报/分享卡片底部嵌入 fittrack://invite?code= 协议内容 | 训练完成页、教学分享卡片已有分享功能 |
| 剪贴板读取 | 首次启动APP时读取剪贴板，正则匹配 FIT-INV-[A-Z0-9]{6} | Flutter clipboard 插件 |
| 剪贴板隐私提示 | 首次读取时顶部浮层提示"发现邀请码，是否激活？[激活][忽略]"，避免"偷看"感知 | 需浮层UI |
| 邀请协议处理 | 监听系统分享/剪贴板两种入口 → 统一跳转邀请码激活页 | 现有邀请码激活页 |
| H5落地页 | 静态页面（GitHub Pages/Vercel免费托管），内容：截图+二维码下载入口 | 无需服务器 |

#### 与纯服务器方案的体验对比

| 维度 | 服务器方案（理想） | 一键链路（v1替代） | 体验差距 |
|---|---|---|---|
| 激活动作 | 扫码→安装→**自动激活**（0步） | 扫码→安装→**点击确认**（1步） | 仅差1次点击 |
| 激励到账 | 实时到账，跨设备累计 | 本地存储，重置后丢失 | v1可接受 |
| 防刷 | 设备指纹彻底防刷 | 仅防自邀，接受多设备损耗 | K因子目标已下调 |
| 教学内容更新 | 云端实时下发 | 发版时更新 | v1阶段内容量30个，无需频繁更新 |
| 开发量 | 服务端+客户端+合规≈15-20天 | 客户端+静态页≈2-3天 | **节省12-17天** |

#### v1 决策结论

| 问题 | 结论 |
|---|---|
| v1是否引入服务器？ | **否**。代价远大于收益，且v1核心目标为"获客留存验证"，非"商业闭环" |
| 裂变流程摩擦 | 通过一键链路补偿，1次点击差距可接受 |
| 防刷和数据继承 | 接受损耗（K因子目标已下调至0.8-1.1），v2服务器方案根治 |
| 教学内容更新 | v1阶段30个基础动作已足够，v1.5服务器方案再实时更新 |

> **调优补充——v1.5服务器方案预留**：
> - v1.5阶段（已验证需求+过渡收入支撑成本）引入轻服务器层
> - 裂变验证服务端：邀请码生成→绑定→激活→奖励发放全链路
> - 内容分发：教学动作库JSON托管CDN，实时更新
> - 仅上传邀请关系+激励记录，不上传任何训练数据/健康数据
> - 成本预估：¥250-500/月，低于v1.5最低解锁收入¥800

### 2.5 高级统计全免费开放

v1阶段全部免费，目的：
- 验证留存数据最干净
- 用户用惯了高级分析，v2收费时"失去感"最强
- 包含：肌群雷达图、渐进负荷曲线、PR突破日历、热力图升级（频次+强度+PR标记）

### 2.6 训练彩蛋（可变奖励）

每次训练完成后20%概率触发彩蛋：里程碑/PR突破/连续打卡/总量里程碑/肌群平衡。
可分享，制造"今天有惊喜"的期待。

> 调优说明：建议将概率设为可配置参数（默认20%），上线后可根据分享率数据动态调整。若分享率低于预期可调至25%，若用户反馈"太频繁"可调至15%。彩蛋触发后建议增加"轻量愉悦动效"（无需完整成就弹窗），降低触发后的流失率。

### 2.10 训练笔记——情感共鸣型分享与留存

#### 问题分析

v1 已有数据型分享（训练完成卡片）和知识型分享（教学卡片），但缺少**情感共鸣型**分享出口。"训练日记""健身打卡日记"是小红书热门品类，纯数据卡片传播力弱，用户需要能表达训练感受的出口。

#### 方案描述

用户可记录每次训练的心得，通过结构化引导降低写作门槛，生成精美笔记海报分享，海报底部带APP名称+logo+邀请码，每次分享都是品牌曝光+裂变入口。

核心机制：

- **绑训练记录与不绑定均可**：用户可选择将笔记绑定到某次训练记录（海报同时展示数据+心得），也可独立写笔记不绑定训练（纯心得/感悟），随用户心意
- **结构化引导**：不提供空白文本框，给结构化模板降低写作门槛
- **笔记海报**：系统自动生成精美海报，含训练数据+心得+APP品牌+邀请码
- **笔记回顾**：历史记录可回看笔记，月度快照含"本月笔记精选"，30天回顾推送"30天前你写道..."

笔记内容结构：

```
训练笔记
├── 绑定训练（可选）：选择关联的训练记录 / 不绑定
├── 训练感受（滑块：轻松 ←→ 爆炸）
├── 最满意的一个动作（选择+一句话，绑定训练时自动填充）
├── 身体状态（可选：酸痛部位标记）
├── 自由心得（文本，限200字）
└── 心情贴纸/Emoji
```

笔记海报样式：

```
┌─────────────────────────────┐
│  🔥 今日训练日记              │
│                              │
│  📅 2026.07.14               │
│  🏋️ 胸部+三头 · 75分钟        │
│  📊 总重量 4,200kg · 24组     │
│                              │
│  💬 "卧推终于突破80kg了，       │
│      上个月还只能推75，        │
│      坚持有用。"              │
│                              │
│  感受：🔥爆炸                  │
│  最满意：卧推 PR+5kg          │
│                              │
│  ─────────────────           │
│  FitTrack 燃力                │
│  纯本地·无广告·你的训练日记     │
│  输入邀请码 FIT-INV-XXXXXX    │
└─────────────────────────────┘
```

触点设计：

```
训练完成页：[写笔记] 按钮（可选，不强制）
历史记录详情：展示该次训练的笔记（如有）
独立入口：首页或个人中心"训练笔记"入口，可写不绑定训练的笔记
笔记列表页：按时间倒序展示所有笔记
月度快照：含"本月笔记精选"（用户标记最满意的几次）
30天回顾推送："30天前你写道'终于能做引体了'，现在呢？"
```

留存钩子：

- 笔记回顾：历史记录详情页展示该次训练笔记，让用户重温训练感受
- 月度笔记精选：月度快照中展示用户最满意的笔记，情感锚点
