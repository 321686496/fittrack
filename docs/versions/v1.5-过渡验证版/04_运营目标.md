## 二、需求验证策略

### 2.1 验证逻辑

v1.5 的核心价值不是收入，而是**验证"用户是否愿意为高级功能付出代价"**：

```
用户使用智能推荐（免费）→ 使用率高（≥40%）
→ v2推出增强版Pro → 用户已尝到甜头，转化概率高

用户看广告解锁专题教学 → adgate使用率高（≥25%）
→ v2推出Pro免广告 → 用户愿意为"不用看广告"付费

用户使用基础编排 → 使用率≥20%
→ v2推出增强版编排（Pro） → 用户已有需求基础
```

### 2.2 验证数据收集

| 数据点 | 收集方式 | 验证目的 |
|---|---|---|
| 智能推荐采纳率 | 本地埋点：推荐显示次数 / 采纳次数 | v2增强版Pro转化潜力 |
| 疲劳度查看频率 | 本地埋点：每周查看次数 | v2疲劳增强版Pro价值 |
| adgate内容类型偏好 | 本地埋点：各类内容点击率 | v2 Pro内容优先级 |
| adgate广告完成率 | 本地埋点：播放完成 / 中途跳过 | 广告收入潜力 |
| 用户流失节点 | 本地埋点：广告展示后7日留存对比 | 广告是否导致流失 |

### 2.3 验证结论判断

| 数据结果 | 结论 | v2行动 |
|---|---|---|
| 智能推荐≥40% + adgate≥25% | 需求验证通过 | 启动v2，Pro以智能推荐增强版为核心 |
| 智能推荐≥40% + adgate<25% | 功能有需求但广告无吸引力 | v2降低广告依赖，直接Pro转化 |
| 智能推荐<40% + adgate≥25% | 功能需求弱但广告变现可行 | v2优化功能设计，广告作为补充收入 |
| 智能推荐<40% + adgate<25% | 需求和变现都不达标 | 暂缓v2，回v1优化产品 |

## 四、v1.5 轻服务器层运营

### 4.1 服务器定位

v1.5正式引入轻服务器层，弥补v1纯本地方案的裂变流程摩擦、防刷薄弱、教学内容更新滞后等问题。

**核心原则**：只上传邀请关系+激励记录，不上传任何训练数据/健康数据/个人信息。

### 4.2 服务器能力与运营对应

| 服务器能力 | 运营价值 | 维护要求 |
|---|---|---|
| 裂变验证服务端 | 被邀请者激活后自动入账，无需二次确认；邀请关系云端保存不丢失 | 每月检查邀请数据异常（刷量） |
| 内容分发（CDN） | 教学动作库实时更新，新动作即时可见，无需用户发版 | 每月更新1-2个教学动作JSON |
| 用户系统（轻） | 匿名ID绑定，跨设备继承激励次数 | 无需运营，自动运行 |
| 防刷增强 | 服务端设备指纹预处理，为v2数据积累基础 | 监控邀请异常波动 |

### 4.3 成本与收入平衡

| 项目 | 金额 | 说明 |
|---|---|---|
| 月服务器成本 | ¥250-500 | 云函数+MySQL+CDN |
| 月解锁收入目标 | ≥¥800（最低）/ ≥¥1,500（理想） | 服务器成本远低于解锁收入 |
| 成本占收入比 | 30-60%（最低标准）/ 15-30%（理想标准） | 健康范围 |

> v1.2调优说明：服务器成本低于v1.5最低解锁收入¥800，财务可持续。

### 4.4 隐私合规运营

| 动作 | 频率 | 耗时 |
|---|---|---|
| 隐私政策页面更新 | v1.5上线前 | 1h |
| 首次启动弹窗（说明上传内容） | 自动 | 无需运营 |
| 数据删除入口维护 | 自动 | 无需运营 |
| 合规检查 | 每季度 | 30min |

### 4.5 一键裂变流程运营

| 优化项 | v1纯本地 | v1.5+轻服务器 | 运营价值 |
|---|---|---|---|
| 被邀请者激活流程 | 扫码→安装→点击确认（1步） | 扫码→安装→自动激活（0步） | 激活率+20% |
| 邀请关系保存 | 本地，重置丢失 | 云端，永久保留 | 用户信任+留存 |
| 激励次数累计 | 本地计数，重置清零 | 服务端保存，可累计 | 邀请积极性+ |
| 防刷 | 仅防自邀 | 服务端校验 | K因子更真实 |
| 教学内容更新 | 发版时更新 | 云端实时下发 | 获客内容丰富度+ |
