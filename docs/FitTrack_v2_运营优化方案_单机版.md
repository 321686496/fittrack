# FitTrack 燃力 v2 运营优化方案（单机版草稿）

> 版本：v2.1-draft | 更新日期：2026-07-14 | 文档状态：优化草稿
> 本文档基于原《FitTrack运营方案.md》与《FitTrack_v2_产品需求文档.md》重构，针对纯单机、个人开发者、无服务器约束下的运营策略优化。
> 目标：高月活/日活、高用户留存率、高Pro支付意愿、高使用率，广告植入克制。

---

## 一、约束与定位

### 1.1 硬约束

| 约束 | 说明 | 影响 |
|------|------|------|
| 纯单机 | 无服务器、无云函数、无网络依赖 | 无法做服务器验证、匿名埋点回收、实时排行榜 |
| 个人开发者 | 无团队、无外包预算、日均运营≤30分钟 | 排除私域社群运营、KOC现金分成、日更内容矩阵 |
| 联网版推迟 | 单机验证可行后再考虑 | 第一版必须靠单机机制驱动增长 |
| 广告克制 | 国内用户对"广告APP"零容忍 | 广告位必须极少、必须用户主动触发、必须提供明确价值 |

### 1.2 核心差异化定位（不变）

> **"你的私人训练笔记本 —— 纯本地，不追踪，不骚扰，只做好一件事：帮你记录每一次训练。"**

v2 在保持纯本地优势的前提下，通过**单机可闭环的机制设计**解决留存、粘性、变现问题。

### 1.3 方案重构思路

原方案问题：功能铺得多但钩子都浅——热力图看一次就腻、徽章解锁一次就忘、广告位过多伤害体验、Pro定价过低损害价值感知。

重构核心：**从"功能堆叠"转向"深钩子设计"**，每个机制都瞄准一个核心指标，且全部单机可实现。

## 二、单机版三大深钩子

### 2.1 虚拟对手——解决单机无社交的粘性短板

#### 问题分析

纯单机APP最大短板是零社交粘性，用户随时可换APP（数据导出JSON即走）。联网版可以上排行榜，但单机版必须有替代方案。

#### 方案描述

APP预埋100个虚拟用户训练数据，覆盖不同水平（新手/进阶/大神），让每个用户都能找到"像真人"的对手。

核心机制：

- **水平分层**：虚拟用户按周训练频次分为4层——休闲（1-2次/周）、规律（3-4次/周）、活跃（5-6次/周）、硬核（7次+）。新用户默认匹配"休闲-规律"层级的对手。
- **动态数据生成**：虚拟对手的训练数据由本地随机种子+用户水平动态生成，符合健身规律（每周3-5次、每次40-70分钟、重量递进），避免穿帮。
- **PK维度**：每周一重置PK，比"本周训练天数"和"本周总重量"两个维度。
- **胜负反馈**：赢了得徽章+弹窗庆祝；输了不惩罚，显示"下周再来"。对手数据保持紧逼感（差距5-15%），让用户感到"差一点就能赢"。

触点设计：

```
首页卡片："本周训练3次，超越了62%的同水平用户"
个人中心："虚拟训练伙伴·小明" [本周训练4次 总重量8,500kg] vs [你：3次 6,200kg]
训练完成后弹窗："本周PK 2:1 领先！再赢一次就锁定胜局"
```

技术实现（纯单机）：

```dart
// 虚拟对手数据模型
class VirtualOpponent {
  String id;
  String nickname;
  String level; // casual/regular/active/hardcore
  int weeklyTrainings; // 本周训练次数
  int weeklyWeight; // 本周总重量(kg)
  int avatarSeed; // 用于生成固定头像的随机种子
}

// 每周日凌晨生成本周对手列表（本地随机，按用户水平分层匹配）
// 用户每次训练后，对手数据做小幅随机增量（模拟真人也在练）
// 对手数据不持久化到历史，每周重置
```

预期指标：DAU/MAU +8-12%，训练完成率+5%

### 2.2 历史记录7天限制——解决Pro支付意愿的刚需钩子

#### 问题分析

原方案核心限制是"3个训练计划"，但对90%用户来说3个计划足够，形同虚设。Pro权益缺乏"用得越久越必须付费"的刚需钩子。

#### 方案描述

将核心限制从"计划数"改为"历史记录查看深度"——免费版只能看近7天记录，Pro看全部。这是真正的"用得越久越必须付费"的钩子。

功能分层重构：

| 功能 | 免费版 | Pro版 |
|------|--------|-------|
| 训练计划数 | 3个 | 无限 |
| **历史记录查看** | **近7天** | **全部** |
| 高级统计（雷达图/负荷曲线/PR日历） | 不可用 | 全部可用 |
| 数据导出（JSON/CSV） | 不可用 | 可用 |
| 主题系统 | 2套 | 全部7套 |
| 桌面卡片（HarmonyOS） | 不可用 | 可用 |
| 训练计划分享码导入 | 不可用 | 可用 |
| 广告 | 有（仅2个激励位） | 完全无 |
| 虚拟对手 | 可用 | 可用（非Pro专属，保持粘性） |

关键体验设计：

- 第8天起，历史记录页面显示"近7天X条记录 · 更早记录已锁定"，引导升级
- 高级统计页面预览一张模糊图（如肌群雷达图），点击弹出"升级Pro查看完整报告"
- 免费用户可"看1次详细报告"（激励视频），第2次起引导升级

预期指标：30天后的Pro转化率+50-80%，ARPU +40-60%

### 2.3 训练计划分享码——解决UGC生态和下载裂变

#### 问题分析

纯单机无服务器，无法做传统UGC平台。但健身APP最核心的社交货币是"训练计划分享"——Keep的核心壁垒就是UGC计划库。

#### 方案描述

用户创建的训练计划可导出为6位分享码（本地JSON压缩+Base32编码），其他用户输入分享码即可导入计划。零服务器、纯本地实现。

分享码格式：

```
FITT-XXXXXX（6位字母数字，校验前缀FITT-）
编码内容：计划名称 + 动作列表 + 组数/重量/次数配置
容量上限：单个计划≤50个动作，压缩后≤200字符
```

触点设计：

```
训练计划页：[导出分享码] → 弹窗显示6位码，支持复制
设置页：[导入计划] → 输入6位码 → 解析验证 → 导入成功
小红书/抖音内容：评论区"回复想要的计划，我发你分享码"
分享卡片底部：输入分享码FITT-XXXXXX可导入我的训练计划
```

运营素材（零成本内容营销）：

- 每周发布3-5套不同目标的训练计划分享码（增肌/减脂/力量/新手/分化）
- 内容平台评论区引导："想要这套5分化计划？评论区扣1，私信发你分享码"
- 分享码自带作者署名（用户自定义昵称），形成轻量创作者激励

预期指标：分享率+20%，新用户激活+15%

## 三、留存提升机制

### 3.1 新手7天留存链

Day 1 已完成（B1新手引导）——后续补充：

```
Day 2：本地通知推送"昨天的训练数据已保存，今天试试背部？"
       （基于Day1选择的部位推荐拮抗肌群）
Day 4：若未训练，首页显示温和引导"休息一下也不错，看看你的训练日历"
Day 7：弹窗"你已经用FitTrack一周了，这是你的第一份周报"
       （本地计算：本周训练天数、总重量、连续打卡天数）
Day 14：推送"你的训练日历已有14个方块，继续加油"
Day 30：首页弹窗"月度进步快照"（与Day1数据对比）
```

技术实现：全部本地通知，无网络依赖。通知触发条件本地判断（daysSinceInstall / daysSinceLastTraining）。

预期指标：次日留存+10%，7日留存+15%

### 3.2 训练计划进度链 + 中断补救

每增加一个训练计划时，本地计算并展示：

```
当前进度：█░░░░░░░░░ 20%（2/10次）
预计完成：还有3周
下次训练：周三 · 背部 + 二头肌
```

中断≥3天时，下次打开APP首页顶部温和引导：

```
"你的『胸背腿循环』计划已等你3天，今天补一练？"
[开始训练] [暂时跳过]
```

中断≥7天时，引导文案改为：

```
"休息一周了，身体恢复得怎么样？来一组轻重量唤醒肌肉记忆吧"
```

中断≥15天：不主动引导，避免打扰。

预期指标：7日留存+8-12%，30日留存+5-8%

### 3.3 数据沉淀锚点——"训练资产化"

首页增加训练资产卡片（纯本地计算）：

```
┌─────────────────────────────────┐
│  📊 你的训练资产                  │
│                                 │
│  累计训练  42 天                  │
│  总重量    48,500 kg             │
│  ≈ 举起了一头成年亚洲象 🐘         │
│  连续打卡  最长 14 天             │
│                                 │
│  本周PK   2:1 领先              │
└─────────────────────────────────┘
```

每30天自动生成月度进步快照，首页弹窗一次：

```
"你这个月训练了18次，比上月多3次，总重量提升12%"
[查看详情] [分享]
```

预期指标：卸载率-15%，DAU/MAU +3-5%

### 3.4 推送策略重构（本地通知）

原方案"≥3天未训练→不推送"是错的，恰恰应该温和召回。重构后：

| 用户状态 | 推送时机 | 文案 | 频次上限 |
|---------|---------|------|:--------:|
| 训练日前一晚 | 21:00（用户可配） | "明天是你的训练日，早点休息" | 周1次 |
| 训练日当天 | 用户配置时间 | "今天是你的训练日，准备好了吗？" | 周1次 |
| 中断3天 | 第4天上午 | "休息几天了，今天轻松练一下？" | 总1次 |
| 中断7天 | 第11天 | "你的训练日历还有X个方块，别让它断了" | 总1次 |
| 中断15天 | 停止推送 | （不召回，避免反感） | - |
| 7天全勤 | 当日训练后 | "7天全勤！超越了85%的用户" | 周1次 |
| **全局限制** | - | - | **7天≤3次** |

关键改进：删除"≥3天不推送"规则，改为温和召回；全局频次从"7天2次"放宽到"7天3次"（增加训练日当天提醒）。

预期指标：DAU +5-8%，召回率+10%

## 四、Pro定价与权益体系

### 4.1 定价阶梯化

原方案"¥18终身买断"损害价值感知，且无涨价空间。重构为三档：

| 档位 | 价格 | 权益 | 定位 |
|------|------|------|------|
| 免费 | ¥0 | 基础功能+2广告位 | 获客 |
| 月卡 | ¥9.9 | Pro全权益30天 | 降低尝试门槛 |
| 年卡 | ¥38 | Pro全权益365天 | **主推档**（日均¥0.1） |
| 终身 | ¥68 | Pro永久 | 高价值用户 |

首发期运营：

- 年卡限时¥18（替代原"终身¥18"），仅前30天可用，制造稀缺感
- 锚点展示："终身¥68（划线）→ 年卡限时¥18"
- 不再卖"终身¥18"，保护价值感知

预期指标：ARPU +40-60%，转化率持平或略升

### 4.2 7天Pro试用

新用户注册后自动获得7天Pro全功能试用（本地计时）：

```
试用期内：所有Pro功能开放，顶部常驻"试用剩余3天"
试用结束前1天：推送"你的Pro试用明天结束，年卡限时¥18"
试用结束：Pro功能锁定，但保留试用期内生成的数据
          （如高级统计图表），让用户"看到失去的东西"
```

技术实现：首次启动记录时间戳到SharedPreferences，每次启动计算天数差。

预期指标：Pro转化率从<1%提升至3-5%

### 4.3 Pro专属训练计划库

APP预置20套专业训练计划（本地存储），仅Pro用户可导入：

| 分类 | 计划数 | 示例 |
|------|:------:|------|
| 增肌 | 5套 | 5x5力量增肌、胸背超级组、渐进超负荷 |
| 减脂 | 4套 | HIIT燃脂、全身循环、代谢力量 |
| 新手 | 4套 | 全身适应、动作学习、基础力量 |
| 分化 | 4套 | 推拉腿三分化、上下肢两分化 |
| 居家 | 3套 | 徒手增肌、弹力带训练、哑铃全身 |

每套计划带"作者说明"（虚拟教练人设，增加专业感），免费用户可预览但不可导入。

预期指标：Pro感知价值+30%，转化率+15%

### 4.4 兑换码分销改"返券模式"

原方案现金佣金40-50%不可持续，改为零现金流出：

- KOC不拿现金，拿**"等值Pro兑换码"**自用或转赠
- 每月给活跃KOC发放3-5个年卡兑换码（成本=0，单机验证无成本）
- KOC转赠给粉丝，粉丝免费得年卡→体验后部分转化终身卡
- 避免现金流出，同时激励KOC

兑换码体系保持原方案（HMAC-SHA256本地验证+多密钥轮换+季度轮换机制不变）。

预期指标：分销成本-100%（零现金流出），KOC活跃度+30%

## 五、广告策略（克制版）

### 5.1 核心原则

**广告 = 用户主动选择换取价值，而非被动打扰**

### 5.2 广告位（仅2个，全部用户主动触发）

| 广告位 | 类型 | 触发 | 频次 | 用户获得 |
|--------|------|------|------|---------|
| **训练完成详细报告** | 激励视频 | 用户主动点击"看广告解锁详细数据" | 不限（用户主动） | 详细肌群分析、疲劳度报告 |
| **Pro试用延长** | 激励视频 | Pro试用期内/结束后，用户主动点击 | 每天1次 | 看广告得1天Pro延期 |

### 5.3 删除的广告位

- ❌ **开屏广告**：国内用户最讨厌，第一印象差，卸载率高
- ❌ **组间休息banner**：干扰训练核心流程，违背"纯本地无打扰"定位
- ❌ **设置页广告**：无意义，徒增反感

### 5.4 广告体验保障

- 激励视频必须可跳过（15秒后可关闭，即使没看完）
- 广告加载失败→静默跳过，不阻塞用户
- Pro用户完全不展示任何广告入口（连"看广告"按钮都不显示）
- 广告SDK选择：优先华为广告（鸿蒙契合），其次穿山甲；不接优量汇（填充率低且体验差）

### 5.5 广告收入预期

| DAU | 日均广告展示 | eCPM | 月广告收入 |
|-----|------------|------|----------|
| 1,000 | 80-150次 | ¥25 | ¥600-1,100 |
| 5,000 | 400-750次 | ¥25 | ¥3,000-5,600 |
| 10,000 | 800-1,500次 | ¥25 | ¥6,000-11,200 |

比原方案3广告位收入低约20-30%，但**留存和口碑提升带来的Pro收入增长远超广告损失**。

## 六、数据可视化升级（让用户每周都想看）

### 6.1 肌群雷达图

展示近30天各肌群训练量分布，一眼看出"练胸太多练腿太少"。

- 数据源：本地训练记录按动作-肌群映射聚合
- 展示位置：统计页顶部 + Pro专属（免费版显示模糊预览）
- 交互：点击某个肌群点→显示该肌群最近训练的动作列表

### 6.2 渐进负荷曲线

每个动作的重量变化曲线，PR突破点高亮标记。

- 数据源：本地训练记录按动作+日期聚合
- 展示位置：动作详情页 + 统计页
- PR标记：当某次训练重量超过该动作历史最大值时，曲线上高亮标记"PR!"

### 6.3 PR突破日历

标记每次突破个人记录的日期，点击查看详情。

- 数据源：本地训练记录逐日扫描，检测重量/次数/组数突破
- 展示位置：统计页 + 首页卡片（"距上次PR已过去X天"）
- 激励：连续30天无PR时，首页温和提示"试试增加重量或次数？"

### 6.4 训练热力图升级

从单纯频次→频次+强度（颜色深浅=训练量）：

```
无训练 = 浅灰底色(#EBEEF0)
训练<30min = 浅蓝(#BBDEFB)
训练30-60min = 中蓝(#42A5F5)
训练>60min = 深蓝(#1565C0) + 高光边框
PR突破日 = 金色标记(#FFD54F)
```

预期指标：用户主动打开率+15-20%

## 七、训练彩蛋（可变奖励）

每次训练完成后，有20%概率触发"训练彩蛋"：

| 彩蛋类型 | 触发条件 | 文案示例 |
|---------|---------|---------|
| 里程碑 | 训练天数达10/30/100/365 | "今天是你第100次训练！" |
| PR突破 | 某动作重量/次数创新高 | "卧推80kg突破！PR+5kg" |
| 连续打卡 | 连续训练达7/14/30天 | "训练日历连续30天有方块！" |
| 总量里程碑 | 累计重量达1t/10t/50t | "累计举起10吨！约等于一头蓝鲸" |
| 肌群平衡 | 近7天所有肌群都练过 | "均衡训练周！你的肌肉感谢你" |

普通训练（80%）：无彩蛋，仅正常庆祝动画。

彩蛋可分享（生成带彩蛋信息的分享卡片），制造"今天有惊喜"的期待。

预期指标：训练完成率+8%，分享率+10%

## 八、指标达成路径

## 十一、风险与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|:----:|------|---------|
| 虚拟对手被用户识破 | 中 | 信任受损 | 数据生成符合健身规律，每周重置，对手昵称/头像/训练时间随机化 |
| 历史记录限制引发差评 | 中 | ASO受损 | 弹窗明确告知"训练数据永久保存，仅查看权限限制"，非删除数据 |
| 广告SDK在鸿蒙不适配 | 中 | 广告收入归零 | 华为广告优先，穿山甲兜底；广告失败静默跳过 |
| 定价调整引发早期用户不满 | 低 | 口碑 | 已购终身用户保持终身权益不变，仅新用户适用新定价 |
| 分享码被批量破解 | 低 | 分销体系受损 | 分享码仅含计划配置，不含Pro权益（与兑换码严格区分） |
| 竞品（Keep/训记）跟进单机+无广告 | 中 | 差异化被追平 | 持续深耕鸿蒙原生+虚拟对手+分享码生态 |

## 十四、后续联网版衔接

本方案所有设计均为联网版预留接口，不影响后续平滑升级：

| 单机版实现 | 联网版升级路径 | 前置条件 |
|-----------|--------------|---------|
| 虚拟对手（预埋假数据） | 真实用户排行榜 | 需服务器 |
| 历史记录本地限制 | 同步云端后解锁全历史 | 需服务器 |
| 训练计划分享码（本地JSON） | UGC计划库（服务器存储+推荐算法） | 需服务器 |
| 兑换码本地验证 | 服务器验证（更安全+防多设备） | 需服务器 |
| 匿名统计开关（默认关） | 匿名埋点上传 | 需服务器 |

单机版验证的核心指标：DAU/MAU≥35%、7日留存≥30%、Pro转化率≥4%——达到即说明模式可行，可启动联网版开发。
