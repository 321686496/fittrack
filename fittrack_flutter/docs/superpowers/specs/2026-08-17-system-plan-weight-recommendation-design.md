# 系统训练计划自动填充重量设计

> 日期：2026-08-17
> 状态：已审阅通过

## 1. 概述

系统训练计划 JSON 中的动作没有重量字段（`weight: null`），采用计划后训练时重量输入框为空，需要用户手动输入。本功能在用户采用系统训练计划时，根据用户填写的身体信息（体重、性别、训练水平）自动估算每个动作的建议重量，并通过确认页让用户核对/修改后保存到计划中。

**核心目标：**
1. 采用系统训练计划时自动填充每个动作的重量，不能为空（自重动作除外）
2. 提供确认页，用户可核对并修改 app 填充的重量
3. 若用户有该动作的最近训练历史记录，优先使用历史重量填充

## 2. 架构方案

**选定方案 A：独立重量推荐服务 + 独立确认页**

- 新增 `WeightRecommendationService` 负责动作分类、估算计算、历史匹配，与现有 `PlanRecommendationService` 模式一致，可独立单测
- 新增 `plan_weight_confirm_page.dart` 确认页
- 系统计划 JSON 数据无需改动（重量在运行时按用户身体信息计算）

## 3. 重量计算模型

### 3.1 动作分类

按动作名关键词匹配，命中即归入对应类别：

| 类别 | 代表动作 | 基础体重占比（入门男性） |
|------|---------|----------------------|
| 复合上肢推 | 杠铃卧推、上斜卧推、杠铃推举、实力举 | 45% |
| 复合上肢拉 | 高位下拉、坐姿划船、杠铃/哑铃划船、直臂下压 | 40% |
| 复合下肢 | 深蹲、硬拉、腿举、罗马尼亚硬拉 | 70% |
| 孤立上肢 | 哑铃飞鸟、弯举、绳索下压、侧平举 | 12% |
| 孤立下肢 | 腿弯举、腿屈伸、提踵、髋外展 | 15% |
| 自重动作 | 俯卧撑、引体向上、卷腹、平板支撑、波比跳 | 不填重量，标"自重" |

分类优先级：自重动作 > 复合下肢 > 复合上肢推 > 复合上肢拉 > 孤立下肢 > 孤立上肢（关键词需覆盖各 JSON 中的实际动作名）。

### 3.2 计算公式

```
建议重量 = 体重 × 类别占比 × 水平系数 × 性别系数
```

- **水平系数**（来自 `Storage.getSettings()['fitnessLevel']`，实际存储值为「新手/初级/中级/高级」）：新手 1.0 / 初级 1.15 / 中级 1.30 / 高级 1.45
- **性别系数**（来自 `Storage.getBodyData()['gender']`，实际存储值为「男/女」）：男 1.0 / 女 0.70
- **历史优先**：训练记录（`Storage.getRecords()`）中按动作名匹配 → 存在则取最近一次该动作的重量作为建议值，来源标记「历史记录」；否则用估算公式，来源标记「估算」
- **取整**：结果取整到 2.5kg，下限 2.5kg

### 3.3 边界处理

- 身体数据缺失（无身高/体重）：使用默认参考体重 65kg 估算，确认页顶部显示提示条「未检测到你的体重信息，按 65kg 估算，可修改下方重量」
- 自重动作：不提供重量输入框，显示「自重」标签，不参与非空校验
- 计算结果超上限：复合动作上限 150kg、孤立动作上限 50kg（防止异常估算）

## 4. 确认页设计（新增 `plan_weight_confirm_page.dart`）

- **顶部**：计划名称 + 副标题「确认每组建议重量，可在下方修改」
- **正文**：按训练日分组（卡片式），每组动作一行：
  - 左侧：动作名 + 「4 组 × 10 次」
  - 右侧：重量输入框（`TextField`，后缀 kg，数字键盘），输入框下方标注来源徽标——「历史记录」或「估算」
  - 自重动作：右侧显示「自重」标签，不提供输入框
- **体重缺失提示条**：检测不到用户身高/体重时显示（非阻断）
- **底部固定栏**：「确认并使用计划」按钮 → 校验所有非自重动作重量非空（空则高亮提示）→ 保存

## 5. 采用流程与数据流

1. 点击「采用此计划」→ 进入确认页（不再直接保存）
2. 确认页通过 `WeightRecommendationService` 计算每个动作的建议重量（历史优先 + 估算回退）
3. 点「确认并使用计划」→ 把重量注入 `toStoragePlan()` 后 `Storage.addPlanAsync` 保存 → 提示 → 回首页
4. 训练页 `_prefillWeightReps()` 现有逻辑自动读到已保存的重量并预填（无需改动训练页）
